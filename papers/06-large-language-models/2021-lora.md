## 한 줄 요약

거대한 사전학습 모델의 가중치는 그대로 두고, 옆에 **작은 행렬 두 개의 곱**만 추가로 학습해서 파인튜닝 비용을 크게 줄였다.

## 왜 중요한가?

모델이 커지면서 파인튜닝이 큰 문제가 되었다. GPT-3(1,750억 파라미터)를 과제마다 통째로 파인튜닝하면, 과제 하나당 1,750억 개짜리 모델 사본이 생기고 학습에 필요한 GPU 메모리도 엄청나다.
LoRA는 GPT-3 기준으로 **학습할 파라미터 수를 약 1만분의 1로, GPU 메모리 요구량을 약 3분의 1로** 줄이면서도 전체 파인튜닝과 비슷하거나 더 좋은 성능을 냈다.
지금은 개인이 LLM이나 이미지 생성 모델(Stable Diffusion)을 자기 데이터로 맞춤 학습할 때 **사실상 표준 방법**이다.

## 핵심 아이디어

### 1. 가정: 파인튜닝 때 바뀌는 양은 "단순하다"

사전학습된 가중치 행렬을 *W*₀, 파인튜닝 후의 가중치를 *W*₀ + Δ*W*라고 하자. 저자들은 Δ*W*가 크기는 크지만 **실제로는 낮은 랭크(low rank)**, 즉 적은 수의 방향만으로 표현할 수 있다고 가정한다.

> 비유: 이미 많은 것을 아는 모델에게 새 과제를 가르치는 것은 "몇 가지 방향으로 살짝 조정"하는 일이지, 처음부터 다시 배우는 일이 아니다.

### 2. 방법: Δ*W*를 작은 행렬 두 개로 쪼개기

*W*₀가 *d* × *k* 행렬일 때, Δ*W*를 직접 학습하지 않고 다음처럼 표현한다.

> Δ*W* = *B* · *A*   (*B*: *d* × *r*, *A*: *r* × *k*, 랭크 *r* ≪ *d*, *k*)

```
          ┌──────────────┐
 x ──┬──→ │  W₀ (고정)    │ ──┐
     │    └──────────────┘   (+)──→ h = W₀x + BAx
     └──→ [A: r×k] → [B: d×r] ┘
           (학습)     (학습)
```

- 예: *d* = *k* = 4096, *r* = 8이면 Δ*W*를 직접 학습할 때는 약 1,677만 개, LoRA로는 *A*와 *B*를 합쳐 약 6만 5천 개 파라미터만 학습한다
- **초기화**: *A*는 무작위, *B*는 0으로 시작한다. 그래서 학습 시작 시점에 *BA* = 0이고, 모델은 원래 사전학습 모델과 똑같이 동작한다
- *BAx*에는 α/*r*배의 스케일을 곱한다. *r*을 바꿔도 학습률을 크게 다시 조정하지 않아도 되게 하는 장치다

### 3. 추론 속도 손해가 없다

학습이 끝나면 *W* = *W*₀ + *BA*를 미리 계산해 **하나의 행렬로 합칠 수 있다.** 그래서 추론 때 계산량이 원래 모델과 똑같다.
이전의 어댑터(adapter) 방식은 층 사이에 작은 신경망을 끼워 넣어서 추론이 느려지는 문제가 있었는데, LoRA는 이를 해결했다.

또 과제마다 작은 *A*, *B*만 저장하면 되므로, 하나의 큰 모델에 여러 LoRA를 갈아 끼우며 쓸 수 있다.

### 4. 어디에 붙이나?

논문에서는 트랜스포머의 어텐션 가중치 중 주로 **Query(*W_q*)와 Value(*W_v*)** 에 LoRA를 붙였다. 랭크는 놀랍게도 *r* = 1~8 정도의 아주 작은 값으로도 충분한 경우가 많았다.

## 읽는 팁

- 먼저 읽기: 1장(서론)과 첫 그림(LoRA 구조), 4장(방법), 5장의 GPT-3 결과 표
- 그다음: 7장(저랭크 업데이트 이해하기). 어떤 가중치에 붙일지, 랭크를 얼마로 할지 실험한 부분으로, 실제로 LoRA를 쓸 때 도움이 된다
- 건너뛰어도 됨: 5장의 RoBERTa, DeBERTa, GPT-2 실험 세부 설정, 7장의 부분 공간 유사도 분석 수식
- 랭크 개념이 낯설다면 "행렬을 몇 개의 독립적인 방향으로 표현할 수 있는가" 정도로 이해하고 넘어가도 충분하다
